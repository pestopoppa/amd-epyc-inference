## Session 1: Phase 3 Validation Overhead Investigation

### Problem

Seeding script (`seed_specialist_routing.py`) showed ~68s overhead on `direct`/`repl` modes but only ~6s on `react` mode. Investigation needed to determine if Python code or server-side.

### Root Cause

**Server-side llama-server overhead, NOT Python code.** The `prompt_ms` and `predicted_ms` from llama.cpp only cover actual model inference. The ~68s is invisible server-side overhead:
- KV cache eviction/reallocation (when `cache_prompt: True`)
- Memory operations (mmap page management, NUMA migration)
- Post-inference cache persistence

### Evidence Pattern

| Previous generation | Overhead | Note |
|---------------------|----------|------|
| 2 tokens | ~6s | LOW |
| 72+ tokens | ~68s | HIGH |
| Cross-server (port 8081 after 8080) | ~68s | **Machine-wide**, not per-server |

### Code Paths Eliminated

All Python code paths investigated and eliminated as overhead source:
- `_architect_plan_review` (not enabled), `_architect_verdict` (skipped for short answers)
- `_formalize_output` (not enabled), `_detect_output_quality_issue` (not enabled)
- `ensure_memrl_initialized` (one-time), `score_completed_task` (lightweight DB)

## Session 3: Role Deduplication in Seeding Script + Random Seeds

### Problem

`frontdoor` and `coder_primary` are the **same model on the same port** (Qwen3-Coder-30B-A3B on `localhost:8080`). The seeding script ran both through all 3 modes (direct, react, repl), producing **6 redundant calls per question** — identical HTTP payloads (skip_suffix=True in all paths eliminates prompt differences).

**Waste**: 70 text questions × 3 wasted calls = 210 redundant inference calls per seeding run. At ~18 t/s with ~2000 tokens avg → ~23,000 wasted seconds (~6.4 hours).

## Session 4: Health Check Fix + Stratified Sampling + MCP + Requirements Audit

### Problem 1: Cascading Health Check Failure

Seeding script's health check used a single `break` when the orchestrator was unhealthy. After frontdoor:react generated 953 tokens (large KV cache), the orchestrator became briefly unresponsive. The `break` at line 528 exited the entire combo loop — coder_escalation (port 8081), architect_general (port 8083), and architect_coding (port 8084) were ALL skipped despite being on separate servers.

### Fix: Per-Role Skip with Retry

Replaced aggressive `break` with per-role `failed_roles` tracking:

| Change | Detail |
|--------|--------|
| `failed_roles: set[str]` tracking | Skip only remaining combos for the failed role, not all combos |
| 5-second retry with 10s timeout | Brief server unresponsiveness gets a second chance |
| `continue` instead of `break` | Other roles on different servers proceed normally |

### Problem 2: Misleading Combo Header

Main log showed "Testing 13 combos" (including coder_primary) even though dedup was active. Confusing output.

### Fix: Separate Tested vs Cloned Counts

## Session 5: Phase 3 Pipeline Performance Optimization

### Problem

Full Phase 3 pipeline (`run_phase3_validation.sh`) takes ~2h24m. Budget analysis:
- 56% seeding (600 calls), 25% learning loop (350 calls), 19% comparison (280 calls across 4 runs)
- All calls sequential through port 8000 (single uvicorn worker)
- 4 redundant API restarts adding ~60s
- Step 6 (kill-switch) over-sampled at 10/suite (only checks binary routing property)

### Optimizations (5 changes, 6 files)

| # | Change | Saves | Files |
|---|--------|-------|-------|
| 1 | Eliminate 2 redundant `restart_api` calls (steps 4, 5 use identical env vars to step 2) | ~30s | `run_phase3_validation.sh` |
| 2 | Runtime feature toggle via `POST /config` endpoint (steps 5b, 6 hot-toggle instead of restart) | ~30s | `src/api/routes/config.py` (NEW), `src/api/routes/__init__.py`, `run_phase3_validation.sh` |
| 3 | Reduce step 6 sample from 10→5 per suite (binary property check, 35 total sufficient) | ~175s | `run_phase3_validation.sh` |
| 4 | Persistent `httpx.Client` in all 3 benchmark scripts (reuse TCP connections) | ~2s | `compare_orchestrator_direct.py`, `seed_specialist_routing.py`, `memrl_learning_loop.py` |
| 5 | Parallel health checks in step 0 (8 ports checked concurrently via background jobs) | ~2s | `run_phase3_validation.sh` |

### `POST /config` Endpoint

New `src/api/routes/config.py` — hot-reloads feature flags without API restart:
```bash
curl -s -X POST http://localhost:8000/config \
  -H 'Content-Type: application/json' \
  -d '{"plan_review": true, "specialist_routing": false}'
# Returns: {"status": "ok", "features": {...}}
```

Uses existing `set_features()` from `src/features.py`. Only applies known feature flag keys; unknown keys ignored.

### Persistent httpx.Client Pattern

All 3 benchmark scripts now create a session-scoped `httpx.Client` at the top of their main loop and pass it as an optional `client=` parameter to API call functions. Falls back to per-call client when `client=None` (backward compatible).
