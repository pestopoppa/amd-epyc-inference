# Progress Report: 2026-02-08

## OpenClaw/Lobster Concept Integration

### Summary
Integrated 8 concepts from OpenClaw (personal AI gateway) and Lobster (typed pipeline runtime) into the pydantic-graph orchestration, organized in 4 phases. All concepts are behind feature flags (default off). 83 new tests added, 2841 total passing (0 failures).

### Changes Made

#### Phase 1A: Side-Effect Declaration (from Lobster)
- Added `SideEffect` enum to `tool_registry.py` with 6 values: `local_exec`, `calls_llm`, `modifies_files`, `network_access`, `system_state`, `read_only`.
- Added `side_effects: list[str]` and `destructive: bool` fields to `Tool` dataclass.
- Updated `load_from_yaml()` to parse side-effect annotations from tool YAML.
- Updated `list_tools()` to include side-effects/destructive only when non-empty.
- Feature flag: `side_effect_tracking`.

#### Phase 1B: Structured Tool Output (from Lobster)
- Added `ToolOutput` dataclass with dual output modes: `to_human()` (text) and `to_machine()` (dict with protocol version).
- Status values: `success`, `error`, `pending_approval`.
- `invoke()` wraps results in `ToolOutput` when `structured_tool_output` enabled.
- Destructive tools return `pending_approval` status when `side_effect_tracking` also enabled.
- Feature flag: `structured_tool_output`.

#### Phase 2A: Model Fallback with Cooldown (from OpenClaw)
- Added `FailoverReason` enum to `roles.py`: `circuit_open`, `timeout`, `connection_error`, `oom`.
- Added `_FALLBACK_MAP` and `get_fallback_roles()` for same-tier alternatives on infrastructure failure.
- Added `classify_failure()` to `BackendHealthTracker` (keyword-based error classification).
- Refactored `_real_call_impl()` in `inference.py`: extracted `_real_call_single()`, added fallback loop iterating `get_fallback_roles()` on failure.
- Feature flag: `model_fallback`.

#### Phase 2B: Content-Addressable LLM Cache (from Lobster)
- Created `src/llm_cache.py`: SHA-256 keyed response cache, JSON on disk, TTL (168h default), LRU eviction (10K max entries).
- Cache key: `SHA-256(prompt | role | n_tokens [| model_hash])`.
- Integrated in `inference.py` before `_real_call_single()` — cache check on entry, cache store after success.
- Added `llm_cache_dir`, `llm_cache_ttl_hours`, `llm_cache_max_entries` to `ServicesConfig` in `config.py`.
- Feature flag: `content_cache`.

#### Phase 3A: Session Compaction (from OpenClaw)
- Added `compaction_count: int = 0` to `TaskState`.
- Added `_maybe_compact_context()` in `nodes.py`: triggers when `turns > 5 AND context > 12000 chars`.
- Uses `worker_summarize` role (44 t/s) to compress old context, keeps last 3000 chars verbatim.
- Called at start of `_execute_turn()` when `session_compaction` enabled.
- Feature flag: `session_compaction`.

#### Phase 3B: Resume Tokens (from Lobster)
- Created `src/graph/resume_token.py`: `ResumeToken` dataclass with `encode()`/`decode()` (JSON -> zlib -> base64url, <500 bytes).
- Added `resume_token: str = ""` to `TaskState`.
- Token generated in `persistence.py` `snapshot_node()` when enabled.
- `run_task()` in `graph.py` accepts `resume_token` param to restore state on resume.
- Feature flag: `resume_tokens`.

#### Phase 4A: Halt-and-Resume Approval Gates (from Lobster)
- Created `src/graph/approval_gate.py`: `HaltReason` enum (`ESCALATION`, `DESTRUCTIVE_TOOL`, `HIGH_COST`), `ApprovalDecision`, `HaltState`, `ApprovalCallback` protocol, `AutoApproveCallback`.
- `should_halt()` checks tier crossing (Worker->Coder = ESCALATION) and high-cost models (architect = HIGH_COST).
- `request_approval_for_escalation()` builds HaltState, calls callback, returns decision.
- Added `pending_approval: Any = None` to `TaskState`, `approval_callback: Any = None` to `TaskDeps`.
- Added `_check_approval_gate()` helper in `nodes.py`.
- Feature flag: `approval_gates` (requires `resume_tokens` + `side_effect_tracking`).

#### Phase 4B: Binding-Based Routing (from OpenClaw)
- Created `src/routing_bindings.py`: `BindingPriority` (DEFAULT=0, CLASSIFIER=10, Q_VALUE=20, USER_PREF=30, SESSION=40), `RoutingBinding`, `BindingRouter`.
- `resolve()` returns highest-priority active binding for a task type.
- `set_session_binding()` / `clear_session_bindings()` for per-conversation overrides.
- Integrated in `chat_routing.py` via `binding_router` param on `_classify_and_route()`.
- Added `binding_router: Any | None = None` to `AppState`.
- Feature flag: `binding_routing`.

#### Feature Flags
- Added 8 new flags to `Features` dataclass in `features.py`, all default `False`.
- Validation: `approval_gates` requires `resume_tokens` AND `side_effect_tracking`.
- All flags in `summary()`, `get_features()` defaults, and env var reading (`ORCHESTRATOR_` prefix).

### Architecture Decisions
1. **All flags default False** — zero behavioral change until explicitly enabled.
2. **Model fallback is distinct from task escalation** — fallback handles infrastructure failure (circuit open, timeout), escalation handles task complexity.
3. **ToolOutput slots into existing `Any` field** — no type changes needed for `ToolInvocation.result`.
4. **Cache skips non-deterministic requests** — only caches when `temperature == 0` and no custom stop sequences.
5. **Session compaction uses worker_summarize** (44 t/s) — cheap and fast enough for summaries.
6. **Resume tokens are compact** (<500 bytes) — JSON + zlib + base64url, no full prompt/context.
7. **Approval gates auto-approve by default** — `AutoApproveCallback` preserves current behavior.

## Streaming Inference Tap (Session 2)

### Summary
Implemented a real-time inference visibility layer activated by `INFERENCE_TAP_FILE` env var. When active, prompts and model output stream to a log file viewable via `tail -f`. Zero performance impact when disabled (O(1) env var check, no I/O). Intercepts at `_call_caching_backend()` in the inference path.

### Design
- **Activation**: `INFERENCE_TAP_FILE=/mnt/raid0/llm/logs/inference_tap.log`
- **Mechanism**: When active, `_call_caching_backend()` uses `infer_stream_text()` (SSE streaming with callback) instead of batch `infer()`. Each SSE text chunk is written to the tap file and flushed. Final SSE event extracts timings. Return type unchanged (`InferenceResult`).
- **Thread safety**: Module-level `threading.Lock` serializes all file writes.
- **Logrotate safe**: File opened/closed per `_append()` call — no stale handles.

## Rich TUI for Seeding Script (Session 3)

### Summary
Implemented a Rich split-screen TUI for the 3-way seeding script, activated via `--tui` flag. Single-command experience: left panel = seeding log, right panel = live inference stream (from tap file), bottom bar = progress status. Also added sentinel file mechanism so the API (separate process) discovers the tap path without env var propagation.

### Design
- **Left panel**: `DequeHandler(logging.Handler)` captures formatted records into `deque(maxlen=500)`. Replaces root logger handlers during TUI lifetime; restores on exit.
- **Right panel**: `TapTailer` daemon thread polls tap file at 50ms. Tracks current section between `========` markers. Handles file-not-yet-created gracefully.
- **Status bar**: `TUIProgress` dataclass updated via `on_progress` callback from `run_batch_3way()`.
- **Sentinel file**: TUI writes `/mnt/raid0/llm/tmp/.inference_tap_active` containing tap path. `inference_tap.py` checks sentinel as fallback (5-second cache, near-zero cost when disabled). Removed on exit + atexit safety.
- **Rich Live**: `SeedingTUI` implements `__rich_console__` protocol — layout rebuilt on every refresh tick (4 Hz).
