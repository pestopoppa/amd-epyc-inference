## Session 1: Wire Vision Requests Through Document Pipeline + REPL

### Problem

VL OCR tests all fail in phase 3 baseline because `_execute_vision()` bypasses the document pipeline entirely. The full pipeline (PDFRouter, DocumentPreprocessor, DocumentChunker, FigureAnalyzer, DocumentREPLEnvironment) was built, tested (48 integration tests), and wired into `/documents` endpoints — but never integrated into the `/chat` flow.

The old `_execute_vision()`:
- Made a bare `client.ocr_image()` call that failed silently
- Hardcoded `tools_used=1` and `tools_called=["ocr_extract"]`
- Returned a single-shot VL model answer bypassing all orchestration

### Changes

5 files modified:

1. **`src/api/routes/chat_utils.py`** — Added `document_result: PreprocessingResult | None = None` to `RoutingResult` dataclass. This carries preprocessing results between pipeline stages.

2. **`src/api/routes/chat_pipeline.py`** — Two changes:
   - **`_execute_vision()`**: Completely rewritten. Now runs `DocumentPreprocessor` on images/files/base64, stores result on `routing.document_result`, returns `None` to fall through to REPL. On failure, injects context note and falls through.
   - **`_execute_repl()`**: When `routing.document_result` is present, creates `DocumentREPLEnvironment` (with `sections()`, `figures()`, `search_sections()` tools) instead of plain `REPLEnvironment`.

3. **`src/api/routes/chat.py`** — After `_execute_vision()` returns None, checks `routing.document_result`. If set, forces `execution_mode="repl"` and `initial_role=Role.FRONTDOOR`.

4. **`src/services/document_preprocessor.py`** — `_extract_document_paths()` now handles `type: "base64"` inputs. Decodes to bytes, detects format from magic bytes (PNG/JPEG/WebP/PDF), saves to temp file on `/mnt/raid0/llm/tmp/`.

5. **`src/api/routes/chat_vision.py`** — No code changes. Old functions (`_handle_vision_request`, `_vision_react_mode_answer`, `_handle_multi_file_vision`) kept for backward compatibility but no longer called from main `/chat` pipeline.

### Data Flow (New)

```
/chat + image → _execute_vision()
                  └─ DocumentPreprocessor.preprocess_file()
                       ├─ PDFRouter (pdftotext + PyMuPDF)
                       ├─ LightOnOCR (port 9001, bbox format)
                       ├─ DocumentChunker (markdown sections)
                       └─ FigureAnalyzer → VL model (figure descriptions)
                  → routing.document_result = PreprocessingResult
                  → return None (fall through)
              → chat.py forces execution_mode="repl", role=FRONTDOOR
              → _execute_repl() → DocumentREPLEnvironment
                  ├─ sections(): list section titles
                  ├─ section(n): get section n content
                  ├─ figures(): list figure metadata
                  ├─ search_sections(query): keyword search
                  ├─ document_info(): metadata dict
                  └─ REPL loop with text model synthesizes answer
```

### WI-9: Staged Reward Shaping (PARL-Inspired Annealing)

**Problem**: MemRL Q-scorer uses a fixed reward signal. PARL (arXiv:2402.03469) shows annealing from shaped→sparse rewards improves policy generalization.

**Changes**:
- Created `orchestration/repl_memory/staged_scorer.py` (~120 lines)
  - `StagedScorer` class with `lambda(step)` annealing from 0.3→0.0 over configurable horizon
  - Exploration bonus `1/sqrt(N+1)` encourages visiting underexplored routes
  - `compute_reward(base, shaping, step, visit_count)` composites all signals
- 8 unit tests in `tests/unit/test_staged_scorer.py`

### WI-10: Parallel Gate Execution

**Problem**: `GateRunner` executes gates sequentially. Schema + format + lint gates are independent and can run concurrently.

**Changes**:
- Modified `src/gate_runner.py`:
  - Added `_run_gate_parallel()` using `asyncio.to_thread()` for subprocess gates
  - Added `run_gates_parallel()` using `asyncio.gather()` for independent gates
  - Sequential fallback preserved for dependent gates
- `parallel_gates` feature flag in `src/features.py`
- 6 unit tests in `tests/unit/test_gate_runner.py` (including `AsyncMock` for awaitable mocks)

## Session 3: Fix orchestrator_eval.py Pre-Launch Bugs

### Problem

Pre-launch review of `orchestrator_eval.py` found three bugs that would silently corrupt MemRL evaluation results:

1. **`mode` field missing from ChatResponse** — The Q-scorer builds action strings as `"role:mode"` (e.g., `"frontdoor:direct"`). Without a `mode` field, eval read `routing_strategy` instead, producing `"frontdoor:learned"` — fragmenting identical execution paths into different Q-values depending on whether MemRL or heuristics chose the route.

2. **`ORCHESTRATOR_REACT_MODE=1` missing from env vars** — Both `orchestrator_stack.py` and `orchestrator_eval.py` restart helpers set all feature flags except react mode. Without it, the heuristic fallback can never route to react mode during cold start.

3. **Direct mode lock-in** — `_should_use_direct_mode()` returns True for ~90% of benchmark prompts (anything with context ≤ 20KB and no file-operation keywords). Direct mode = single LLM call with no tools, no REPL, no self-escalation. MemRL never sees non-direct modes, so it can never learn when tools/escalation help.

### Changes

6 files modified:

1. **`src/api/models/responses.py`** — Added `mode: str = Field(default="", description="Execution mode: direct, react, repl, delegated, or mock")` to `ChatResponse`.

2. **`src/api/routes/chat_pipeline.py`** — Set `mode=` in all 6 `ChatResponse(...)` constructors:
   - `_execute_mock()` → `mode="mock"`
   - `_execute_delegated()` → `mode="delegated"`
   - `_execute_react()` → `mode="react"`
   - `_execute_direct()` → `mode="direct"`
   - `_execute_repl()` (two-stage) → `mode="repl"`
   - `_execute_repl()` (main) → `mode="repl"`

3. **`scripts/benchmark/orchestrator_eval.py`** — Changed `result.get("routing_strategy", "unknown")` to `result.get("mode", "unknown")`. Added `ORCHESTRATOR_REACT_MODE=1` to `restart_orchestrator_api()` env vars.

4. **`scripts/server/orchestrator_stack.py`** — Added `env["ORCHESTRATOR_REACT_MODE"] = "1"` to `start_orchestrator()`.

5. **`src/api/routes/chat_routing.py`** — Changed `_select_mode()` heuristic fallback from `direct → react → repl` to `react → repl`. REPL is a superset of direct (model can `FINAL("answer")` immediately for simple questions, or use tools if needed). This gives MemRL exposure to non-direct modes during cold start.

### Design Rationale

- **Why "repl" as default, not "direct"?** REPL mode is strictly a superset. The model can call `FINAL("answer")` on the first turn for simple questions (equivalent to direct), but it also has the *option* to use tools, escalate, or explore. MemRL learns from outcomes — if direct-style answering works, Q-values will converge to favor immediate FINAL(). But the model needs the opportunity to try tools first.
- **`_should_use_direct_mode()` kept but uncalled from `_select_mode()`**. The function is still defined and importable (test_api_imports.py validates this). It may be useful later when MemRL explicitly learns to choose direct mode.
