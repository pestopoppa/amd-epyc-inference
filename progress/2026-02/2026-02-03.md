## Session 3: Phase 1 Hard Benchmark Adapters (MemRL Mode-Advantage)

### Problem

Overnight MemRL seeding produced 941 memories, but **66% of routing went to frontdoor** with 98%+ success. The original 90 mode-advantage tasks weren't hard enough — Qwen3-Coder-30B-A3B handles modular arithmetic and simple bugfixes trivially.

Real mode-advantage requires tasks where:
1. Frontdoor genuinely fails (<50%)
2. Specialists/tools genuinely succeed (>70%)

Research shows GPT-4/Claude score <50% on GPQA Diamond (39%), SimpleQA (<40%), USACO (8.7%), Spider 2.0 (10.1%). These are ideal for mode-advantage signal.

### Changes

**4 new hard benchmark adapters** in `scripts/benchmark/dataset_adapters.py`:

1. **GPQAAdapter** — Graduate-level science (react >> direct)
   - Source: `ankner/gpqa` (ungated mirror of GPQA Diamond)
   - Size: 448 questions
   - Scoring: `multiple_choice` (A/B/C/D)
   - Tiers: physics/chemistry = T3, biology = T1, other = T2
   - Expected: Frontdoor ~30%, with tools/specialist ~50-60%

2. **SimpleQAAdapter** — Factual accuracy (react+search >> direct)
   - Source: `MAISAAI/openai_simple_qa_test_set`
   - Size: 4,326 questions
   - Scoring: `exact_match` (normalized)
   - Tiers: By answer length/complexity
   - Expected: Direct ~30%, with search tools ~70%

3. **HotpotQAAdapter** — Multi-hop reasoning (react+search >> direct)
   - Source: `hotpotqa/hotpot_qa` (distractor, hard split only)
   - Size: 7,405 questions
   - Scoring: `f1` (new token-level F1 scorer)
   - Tiers: bridge = T2, comparison = T3
   - Expected: Direct ~40%, with search ~80%

4. **LiveCodeBenchAdapter** — Competition programming (repl >> direct)
   - Source: `greengerong/leetcode` (LeetCode problems)
   - Note: Original `livecodebench/code_generation` has deprecated HF loading script
   - Size: 2,360 problems
   - Scoring: `code_execution` or `substring`
   - Tiers: Easy/Medium/Hard from LeetCode tags
   - Expected: Direct ~20%, with REPL ~50%

**F1 scorer** added to `scripts/benchmark/debug_scorer.py`:
- Token-level F1 scoring for QA tasks (SQuAD-style)
- Normalization: lowercase, remove punctuation, remove articles
- Configurable threshold (default 0.5)

**Seeding types** updated in `scripts/benchmark/seeding_types.py`:
- Added all 4 suites to `DEFAULT_SUITES` and `ADAPTER_SUITES`
- Per-suite timeouts: gpqa=180s, simpleqa=120s, hotpotqa=180s, livecodebench=300s

## Session 4: CI Lint Fix (688 errors → 0, pre-commit hook)

### Problem

GitHub Actions CI was failing at the **"Run linter"** step with 688 ruff errors. No pre-commit hook was installed locally, so lint errors accumulated over time without being caught before push.

Error breakdown:
- F401 (unused imports): 314
- E501 (line too long): 289
- F841 (unused variables): 48
- E402 (import order): 18
- F821 (undefined names): 7
- Other: 12

### Root Cause

1. CI workflow used `ruff check --select E,F,W` which overrode pyproject.toml ignore rules
2. pyproject.toml had E501 in ignore list, but CI didn't use it
3. No pre-commit hook to catch errors locally

### Changes

**Auto-fixes** (348 errors):
- `ruff check --fix` for F401, F841, F541
- `ruff format` reformatted 199 files

- Added `# noqa: F401` for intentional availability-check imports (`PIL.Image`, `fitz`, `RestrictedExecutor`)
- Fixed E741 ambiguous variable names (`l` → `line` in chat_review.py)

**Configuration changes**:
- `.github/workflows/test.yml`: Removed `--select E,F,W` to use pyproject.toml config
- `pyproject.toml`: Simplified ruff select to E,F,W only; added E501, E402 to ignore list

**Pre-commit hook**:
- Created `.git/hooks/pre-commit` that runs `ruff check src/ tests/`

### Follow-up Fix: Memory Guard for CI

CI was still failing because `tests/conftest.py` has a memory guard requiring 100GB free RAM. GitHub Actions runners only have ~15GB.

**Fix**: Added `IS_CI` check that skips the memory guard when `CI=true` or `ORCHESTRATOR_MOCK_MODE=true` (both set by GitHub Actions workflow). Mock-mode tests don't load models, so they're safe to run with limited RAM.

### Follow-up Fix #2: Optional chromadb Import

CI was still failing due to `ModuleNotFoundError: No module named 'chromadb'`. The import chain was:
```
test_chat_pipeline.py → src/api/__init__.py → vision.py → pipeline.py →
analyzers/__init__.py → face_embed.py → chroma_client.py → import chromadb
```

chromadb is only needed for face embedding features (vision pipeline), not for orchestrator tests.

**Fix**: Made chromadb an optional import in `src/db/chroma_client.py`:
- Added try/except around chromadb import
- Added `CHROMADB_AVAILABLE` flag
- Added `_require_chromadb()` guard function that raises `ImportError` when called without chromadb
- Updated tests to mock `CHROMADB_AVAILABLE`
