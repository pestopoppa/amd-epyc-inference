## Corpus Index V3: Sharded Build + Pruning

### Summary
Rebuilt corpus index pipeline from scratch after previous day's failed phased approach.
Deleted JS, TS, Go corpora (not needed). Pruning remaining 3 languages by 50% via
deterministic sampling during population into shards.

### Decisions
- **Dropped languages**: JavaScript, TypeScript, Go — not needed for current use cases
- **50% sampling**: `id % 1000 < 500` — uniform across all repos, preserves diversity
- **Dual-cursor merge**: Fixed O(N²) bug in original populate script (per-snippet ngram
  lookups on 6.7B unindexed rows). New approach streams both tables in insertion order.
- **Parallel population**: 3 languages (Python, C++, Rust) processed simultaneously via
  multiprocessing. Shard writes use thread pool (16 threads) with retry on lock contention.
- **Auto-delete temp DBs**: Each language's temp DB deleted after population completes.

## TUI Panel Width + REPL Tap Truncation Fixes

### Problem
1. **Inference/REPL panels not using full width**: Lines manually clipped to `right_width` (`console.width * 5/8 - 6`) before being passed to Rich Panel, which already handles width via `overflow="crop"`. Double-accounting caused content to stop well before panel edge.
2. **REPL tap truncation too aggressive**: `_tap_write_repl_exec()` and `_tap_write_repl_result()` in `src/graph/helpers.py` truncated code at 800 chars, output at 500 chars, errors at 300 chars. Display-only (tap file for TUI), not affecting model execution.

### Fix
- Removed `line[:right_width]` clipping from inference and REPL panel rendering; Rich Layout+Panel handles width natively
- Bumped REPL tap preview limits: code 800→4000, output 500→4000, error 300→2000
- Cleaned up unused `right_width` variable

| `scripts/benchmark/seeding_tui.py` | Removed manual width clipping from inference/REPL panels, removed unused `right_width` |
