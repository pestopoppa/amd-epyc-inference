## Corpus Index V3: Sharded Build + Pruning

### Summary
Rebuilt corpus index pipeline from scratch after previous day's failed phased approach.
Deleted JS, TS, Go corpora (not needed). Pruning remaining 3 languages by 50% via
deterministic sampling during population into shards.

### Decisions
- **Dropped languages**: JavaScript, TypeScript, Go — not needed for current use cases
- **50% sampling**: `id % 1000 < 500` — uniform across all repos, preserves diversity
- **Dual-cursor merge**: Fixed O(N²) bug in original populate script (per-snippet ngram
  lookups on 6.7B unindexed rows). New approach streams both tables in insertion order.
- **Parallel population**: 3 languages (Python, C++, Rust) processed simultaneously via
  multiprocessing. Shard writes use thread pool (16 threads) with retry on lock contention.
- **Auto-delete temp DBs**: Each language's temp DB deleted after population completes.

## claude-mem Plugin: 637 Zombie Workers (231 GB RAM Leak)

### Problem
System RAM at 818 GB with 7.5 GB swap consumed despite a healthy idle orchestration
stack (~570 GB expected). Investigation found **637 orphaned Claude subprocess workers**
(`claude.*stream-json`) spawned by the claude-mem plugin's bun worker daemon (PID 2985064,
`worker-service.cjs`). Workers spawned between Feb 16 19:09 and Feb 17 01:02, consuming
**228 GB RSS + 2.6 GB swap = ~231 GB total**. Additionally, 6 zombie processes found
(5 curl from NextPLAID health checks, 1 speech-dispatcher) — harmless, zero resources.

### Root Cause
claude-mem v9.0.12 had no subprocess concurrency limit. The `SDKAgent.startSession()`
spawned new Claude SDK agent subprocesses without bound. During a heavy session with
many observations queued, the worker kept spawning new agents without reaping old ones.

### Fix
- **Plugin update**: `~/.claude/plugins/marketplaces/thedotmack/` pulled from
  `1341e93` (v9.0.12) → `eea4f59` (v10.2.3). Key upstream fixes:
  - `51719d2` — `CLAUDE_MEM_MAX_CONCURRENT_AGENTS` setting (default: 2),
    `waitForSlot()` in ProcessRegistry with 60s timeout
  - `cd31eaf` — Parent heartbeat for MCP server orphan prevention
  - `a3f9e7f` — 5-layer spawn storm defense ("641 processes → max 2")
- **Cleanup**: Killed 637 workers (SIGTERM, all exited cleanly), restarted bun daemon
- **Result**: RAM 818→577 GB, swap 7.5→0 GB, workers 637→2

### Files / Actions
| Action | Detail |
|--------|--------|
| `git pull origin main` | `~/.claude/plugins/marketplaces/thedotmack/` (v9.0.12 → v10.2.3) |
| `kill <637 PIDs>` | Freed 231 GB RAM |

## Performance: Parallel Tools, Concurrent Sweep, Prefix Cache

Three targeted optimizations addressing real I/O bottlenecks in the orchestration stack. Python overhead is <0.1% of wall time (99.8% is I/O-blocked on llama-server). Rust/C++ rewrite rejected.

### WS1: Parallel Read-Only Tool Execution
AST-based extraction of independent read-only tool calls, dispatched via `ThreadPoolExecutor(max_workers=4)`. Conservative: any ambiguity falls through to sequential `exec()`.

**Files**: `src/repl_environment/parallel_dispatch.py` (new), `environment.py` (integration), `file_exploration.py`/`routing.py`/`code_search.py` (thread-safe counters), `features.py` (`parallel_tools` flag), 22 unit tests.

### WS2: Concurrent Inference Sweep
`scripts/benchmark/concurrent_inference_sweep.py`: asyncio + httpx benchmark for optimal `-np`/concurrency per model tier. Tests 5 roles × varying concurrency. Incremental CSV output, TTFT baseline, streaming probe.

### WS3A: Wire id_slot (Fix Existing Stub)
`PrefixRouter` computed optimal slots but never passed `id_slot` to llama-server. Fixed via `dataclasses.replace(request, slot_id=slot_id)` in `CachingBackend.infer()`. Zero risk (`id_slot=-1` = auto).

### WS3B: Escalation Compression
Feature-flagged (`escalation_compression=False`). When escalating with >16K char prompt, LLMLingua-2 BERT compresses to 50% with code-structure token preservation. Saves ~1.67s per architect escalation at 1.2 t/s prefill.

### WS3C: Pre-warm Architect
`src/services/escalation_prewarmer.py`: At turn 1, if `classify_task_complexity()` returns COMPLEX, fire non-blocking `n_predict=0, cache_prompt=true` to architect server. Checks `/slots` first to avoid evicting hot slots. Saves ~417ms per architect escalation.
